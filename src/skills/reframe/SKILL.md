# reframe

Do not do the task. Start from the operator's own files, code and words, not a summary. If the description could name more than one problem, list the two or three it could be, each with the term that names it and the sign that tells it apart, then pick the likeliest and say why. Give 8 to 12 expert terms ranked by how much each would change what gets built; for each, give a one-sentence meaning, the part of the description it names, one real project, paper or system that uses it that way with a link, and what it lets the operator ask an agent for. Borrow terms from 2 or 3 neighboring fields that solved the same shape of problem under other names; say what carries over and where each analogy breaks. Name what the operator did not mention but should care about, then rewrite their description with the new words. Open every link and confirm it uses the term that way; cut any citation you cannot confirm. Suggest `/sharpen` on the rewrite when depth, not naming, is the remaining gap.
