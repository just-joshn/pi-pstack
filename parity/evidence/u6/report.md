1. **High — The write guard allows an unqualified skill edit (case i).** The unqualified append added `<!-- U6_GUARD_PROBE -->` to the test copy of `how/SKILL.md`; only the later restore removed it. The explicit-edit path worked too, so the guard distinguishes reads but did not enforce the intended write authorization. The file now matches its original hash. Evidence: `i-guards/unauthorized-tool-calls.tsv`, `i-guards/how-SKILL.after-unauthorized.sha256`, `i-guards/how-SKILL.final.sha256`.
2. **Medium-high — setup-pstack resolves host config instead of the isolated Pi directory (case k).** The skill read host `~/.pi/agent/AGENTS.md` and host model files before it was redirected to `$PI_CODING_AGENT_DIR`. The isolated output and model-scope refusal were correct after steering; host config hashes did not change. The earlier `/skill:how` session also read host `AGENTS.md`. Evidence: `k-setup-pstack/host-read-paths.txt`, `k-setup-pstack/host-config-unchanged.txt`, `j-how/main-session.jsonl`, `j-how/run-076a0d84/request.json`.
3. **Medium — poteto-agent cannot attach the package skill from outside the scratch workspace (case n).** Both the absolute package path and a workspace-relative `..` path were rejected, so the requested child reply could not be obtained. Evidence: `n-agent/task-requests.jsonl`, `n-agent/attachment-errors.txt`.
